# Ramus RSF Editor

Нативное настольное приложение (PyQt6) для **Windows, macOS и Linux** для
чтения и редактирования файлов моделей IDEF0/DFD
[Ramus](https://github.com/Vitaliy-Yakovchuk/ramus) (`.rsf`) — построено на
«чистой» (clean-room), реализованной с нуля реконструкции формата файла.
Полное описание процесса реверс-инжиниринга (что подтверждено на реальных
примерах файлов, а что выведено из исходного кода, и известные
ограничения) — в [`RAMUS_RSF_FORMAT.md`](RAMUS_RSF_FORMAT.md).

![Скриншот](docs/screenshot.png)

Не связано с проектом Ramus. `.rsf` — это ZIP-архив из самоописывающихся
XML-таблиц (см. документ о формате) — этот инструмент читает и пишет такой
контейнер напрямую; для его работы не требуется ни сам Ramus, ни JVM.

## Установка в один клик

Готовые установщики для всех трёх платформ публикуются на странице
**[Releases](https://github.com/parnickname/ramus-rsf-decoder/releases/latest)**
при каждом выпуске версии — Python и PyQt6 отдельно ставить не нужно, всё
уже внутри:

| Платформа | Файл | Что делать |
|---|---|---|
| 🪟 Windows | `RamusRSFEditor-Setup-X.Y.Z.exe` | Скачать и запустить — мастер установки на русском, без прав администратора, ярлык в меню «Пуск» и ассоциация файлов `.rsf` ставятся автоматически. |
| 🍎 macOS | `RamusRSFEditor-X.Y.Z.dmg` | Скачать, открыть образ, перетащить значок в **Applications** — готово. |
| 🐧 Linux | `RamusRSFEditor-X.Y.Z-x86_64.AppImage` | Скачать, дать файлу право на исполнение (`chmod +x`) и запустить — установка не требуется, работает на любом дистрибутиве. |

Пользователи Arch Linux могут вместо этого поставить пакет через
`makepkg` — см. [«Установка на Arch Linux»](#установка-на-arch-linux) ниже.

Как эти установщики собираются — в
[`.github/workflows/release.yml`](.github/workflows/release.yml) и
[`packaging/`](packaging/) (PyInstaller-спека + Inno Setup для Windows,
`create-dmg` для macOS, `appimagetool` для Linux).

## Что внутри

- **`ramus-rsf-gui`** — графический интерфейс: просмотр каждого
  квалификатора/элемента в дереве модели, редактирование любого атрибута
  подходящим по типу виджетом (текст, числа, выбор цвета, редакторы
  шрифта/границ/статуса, файловые/HTML-текстовые вложения), универсальный
  редактор-таблица для всего, что не смоделировано отдельно, просмотрщик/
  экспортёр живого JSON-дампа с сопутствующим механизмом
  **редактирования-и-повторного-импорта**, а также диалоги для создания
  новых элементов, новых функциональных блоков IDEF0, **новых стрелок между
  блоками (или к/от границы страницы)** и новых диаграмм, клонированных из
  существующего квалификатора-шаблона.
- **`ramus-rsf-cli`** — сценарный инспектор командной строки (`dump`,
  `qualifiers`, `elements`, `show`, `tables`, `table`, `rename`,
  `import-json`).
- **`ramus_rsf_tool`** — базовая библиотека на Python
  (`rsf_core`/`rsf_model`/`template`), которую можно использовать отдельно
  для написания сценариев; см. примеры в разделе 13
  `RAMUS_RSF_FORMAT.md`.

## Возможности

- **Windows, macOS и Linux** из одной кодовой базы (PyQt6), с готовыми
  установщиками в один клик для всех трёх — см. выше.
- **Светлая и тёмная тема** (`Вид > Тёмная тема`), выбор запоминается между
  запусками.
- Открытие, редактирование и сохранение файлов `.rsf` без потерь
  (побайтово идентичный цикл для всего нетронутого — состояние GUI-сессии,
  вложения, настройки печати).
- Создание новой модели с нуля (`Файл > Создать`) без необходимости в
  файле-шаблоне.
- Полное редактирование атрибутов для стандартного набора
  функционального блока IDEF0: имя, описание (форматированный текст/HTML),
  границы, цвет фона/переднего плана, шрифт, статус, тип.
- Универсальные редакторы для любого другого типа атрибутов в формате
  (Text, Long, Double, Date, Currency, Boolean, Icon, файловые вложения,
  ссылки на элементы, иерархические деревья, таблицы стрелок/секторов,
  формулы, ...) — ничто в файле не остаётся недоступным, даже типы
  атрибутов без выделенного виджета — через вкладку «Сырые таблицы».
- Структурные правки: добавление/удаление/переименование элементов,
  добавление новых квалификаторов, добавление функциональных блоков IDEF0
  со всеми визуальными атрибутами в одном диалоге, **отрисовка новых
  стрелок между двумя блоками или между блоком и границей диаграммы**,
  клонирование набора атрибутов существующей диаграммы для создания новой,
  регистрация новой диаграммы как корня модели верхнего уровня.
- Экспорт всей модели в JSON (или только видимых пользователю
  квалификаторов) для написания сценариев, проверки или передачи в другие
  инструменты.
- **Экспорт, редактирование, повторный импорт**: экспортируйте JSON-дамп,
  отредактируйте/отцензурируйте текст (в приложении или в любом внешнем
  редакторе), затем импортируйте его обратно и сохраните итоговый `.rsf`.
  Импорт — это *патч*: он сопоставляет квалификаторы/элементы по id и
  обновляет только те текстовые/значимые поля, которые реально изменились
  — он никогда ничего не добавляет и не удаляет, поэтому редактирование
  безопасно, даже если вы случайно удалите блок (см. «Редактирование
  файла» ниже).

## Редактирование файла

Вкладка «JSON-дамп» поддерживает весь цикл экспорт → редактирование →
повторный импорт → сохранение:

1. **Вкладка «Атрибуты» / вкладка «JSON-дамп» → Экспорт в файл…**, чтобы
   получить `dump.json`.
2. Отредактируйте его — найдите и замените конфиденциальный текст в своём
   редакторе (или редактируйте поле прямо в приложении — это обычное
   текстовое поле).
3. **Вкладка «JSON-дамп» → Импорт из файла…** (загружает отредактированный
   JSON и сразу же применяет его) — или, если вы редактировали поле на
   месте, **Применить отредактированный текст ниже**. В любом случае вы
   получите сводку о том, что изменилось, и список записей, которые не
   удалось применить.
4. **Файл > Сохранить** (или **Сохранить как…**), чтобы записать
   отцензурированный `.rsf`.

Тот же процесс можно выполнить без GUI, сценарием:

```sh
ramus-rsf-cli dump FILE.rsf --all --pretty > dump.json
$EDITOR dump.json                       # или: sed -i 's/Алиса/[УДАЛЕНО]/g' dump.json
ramus-rsf-cli import-json FILE.rsf dump.json FILE.redacted.rsf
```

Импорт всегда только **применяет патч к значениям, уже присутствующим** в
файле — id квалификатора/элемента из JSON, которого там не существует,
пропускается и попадает в отчёт, но никогда не создаётся, а блок
квалификатора/элемента, который вы удалили при редактировании, просто
остаётся нетронутым, а не удаляется. Атрибуты со значением-списком и
файловые/потоковые атрибуты (дамп показывает для них только количество
байт, а не сами байты) тоже не проходят полный цикл через JSON — их нужно
редактировать во вкладке «Сырые таблицы» или напрямую в редакторе
атрибутов.

## Установка на Arch Linux

Альтернатива установщику в один клик из раздела выше — системный пакет
через `makepkg`.

### Вариант A: makepkg (рекомендуется)

```sh
cd packaging
makepkg -si
```

Это соберёт и установит `ramus-rsf-tool-git`, включая ярлык рабочего
стола, значок и ассоциацию с MIME-типом `.rsf`, используя `python-pyqt6`
из официальных репозиториев Arch. После установки запустите **Ramus RSF
Editor** из меню приложений или выполните:

```sh
ramus-rsf-gui [FILE.rsf]
ramus-rsf-cli --help
```

### Вариант B: pip (любая платформа, включая Arch без makepkg)

Работает одинаково на Linux, Windows и macOS — например, для разработки
или если по какой-то причине не подходит готовый установщик из раздела
выше:

```sh
python3 -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install .
ramus-rsf-gui
```

Для разработки (editable-установка + тесты):

```sh
pip install -e ".[dev]"
pytest
```

## Запуск без установки

```sh
pip install .
python3 -m ramus_rsf_tool.gui.app [FILE.rsf]      # GUI
python3 -m ramus_rsf_tool.rsf_cli qualifiers FILE.rsf   # CLI
```

## Структура проекта

```
ramus_rsf_tool/
  rsf_core.py      слой контейнера: ZIP + обобщённые самоописывающиеся XML-таблицы
  rsf_model.py      семантический слой EAV: квалификаторы/элементы/атрибуты,
                     TYPE_MAP, вспомогательные функции для функциональных блоков IDEF0,
                     dump_model()/apply_json_dump() (экспорт-редактирование-реимпорт)
  rsf_cli.py        инспектор командной строки (также точка входа `ramus-rsf-cli`)
  template.py       строит минимальный валидный архив с нуля (Файл > Создать)
  gui/
    app.py            точка входа GUI (`ramus-rsf-gui`)
    theme.py          переключатель светлой/тёмной темы (QPalette + QSettings)
    main_window.py     меню, панель инструментов, связка панелей, ввод-вывод файлов, отслеживание изменений
    widgets/
      qualifier_tree.py    левый навигатор по квалификаторам/элементам
      attribute_editor.py  редакторы отдельных атрибутов (вкладка «Атрибуты»)
      field_widgets.py     обобщённые построители виджетов по SQL-типу
      raw_table_view.py    обобщённый редактор-таблица (вкладка «Сырые таблицы»)
      json_dump.py         вкладка просмотра/редактирования JSON-дампа (экспорт, редактирование, повторный импорт)
      dialogs.py           Новый элемент / Новый функциональный блок / Новая стрелка / Клонировать квалификатор / ...
      common.py            ColorButton и другие небольшие общие вспомогательные функции
tests/                набор тестов pytest (циклы формата, правки модели, дымовые тесты GUI)
packaging/
  PKGBUILD, ramus-rsf-tool.desktop, ramus-rsf-tool-mime.xml  -- пакет для Arch Linux
  icons/               генератор .ico/.icns/.png из общего SVG-значка (generate_icons.py)
  pyinstaller/         общая .spec-сборка для Windows/macOS/Linux
  windows/             скрипт Inno Setup -> Setup.exe
  macos/                скрипт сборки .dmg (create-dmg)
  linux/                скрипт сборки .AppImage (appimagetool)
.github/workflows/
  release.yml          сборка всех трёх установщиков и публикация в GitHub Releases по тегу vX.Y.Z
  tests.yml             pytest на каждый push/PR
RAMUS_RSF_FORMAT.md   описание реверс-инжиниринга формата файла
```

## Тестирование

```sh
pip install -e ".[dev]"
QT_QPA_PLATFORM=offscreen pytest tests/ -v
```

Тесты GUI запускаются на плагине платформы Qt `offscreen`, поэтому весь
набор тестов (циклы формата, редактирование модели и взаимодействие с GUI)
выполняется без графического окружения в CI или по SSH — X-сервер не
требуется. `QT_QPA_PLATFORM` не нужен, если доступен настоящий дисплей.

## Сборка установщиков локально

Установщики из раздела «Установка в один клик» собираются автоматически в
GitHub Actions ([`.github/workflows/release.yml`](.github/workflows/release.yml))
при каждом теге `vX.Y.Z`, но те же шаги можно выполнить и локально на
соответствующей ОС:

```sh
pip install . pyinstaller
pyinstaller packaging/pyinstaller/ramus-rsf-gui.spec --noconfirm
```

Дальше, в зависимости от платформы:

```sh
# Windows (нужен установленный Inno Setup 6): результат -- dist/installer/*.exe
iscc packaging\windows\ramus-rsf-tool.iss

# macOS (нужен create-dmg: brew install create-dmg): результат -- dist/installer/*.dmg
packaging/macos/build_dmg.sh 1.1.0

# Linux (appimagetool скачается автоматически): результат -- dist/installer/*.AppImage
packaging/linux/build_appimage.sh 1.1.0
```

Значки во всех трёх установщиках генерируются из одного SVG
(`ramus_rsf_tool/gui/resources/ramus-rsf-tool.svg`) скриптом
`packaging/icons/generate_icons.py` — перезапускать его нужно только если
менялся сам SVG, готовые `.ico`/`.icns`/`.png` уже лежат в репозитории.

## Известные ограничения

Унаследовано от лежащего в основе реверс-инжиниринга формата (подробности
в `RAMUS_RSF_FORMAT.md`):

- **Многосегментные (изогнутые) стрелки** не поддерживаются отдельным
  помощником — `Правка > Новая стрелка…`/`Model.add_arrow()`/
  `add_boundary_arrow()` создают прямую, автоматически проложенную стрелку
  между двумя блоками или между блоком и границей диаграммы (побайтово
  совпадает с реальными данными Ramus, проверено на реальных образцах
  файлов и на исходном коде отрисовки стрелок Ramus — раздел 10), что
  покрывает типичный случай. Изгиб стрелки или редактирование стрелки с
  более чем одним сегментом всё ещё требует вкладки «Сырые таблицы».
  - **Связывание функционального блока с его собственной дочерней
    диаграммой декомпозиции** не поддерживается; поддерживается только
    регистрация *нового корня модели верхнего уровня* (раздел 9).
- Ничего из вышеперечисленного не было подтверждено открытием выходных
  файлов в настоящем GUI Ramus (во время разработки не было доступно
  инструментов JVM/Gradle) — вместо этого корректность проверялась
  исчерпывающим циклическим тестированием (round-trip) и редактированием
  реальных образцов файлов `.rsf` с опорой на реконструированные правила
  кодирования. Точный список того, что было и не было проверено — в
  разделе 14 `RAMUS_RSF_FORMAT.md`.
